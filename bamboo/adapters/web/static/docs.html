Bamboo CLI Documentation

Bamboo 命令使用说明

这份说明只覆盖使用者直接接触的 bamboo 命令、模型配置和常见启动方式。 不包含内部执行流程、Web API 或运行时实现细节。

Python 3.11+ CLI Web Model config

功能概览

一次性任务

用 bamboo run 或 bamboo main --msg 直接执行一条任务。

交互式会话

用 bamboo main 进入多轮命令行会话，支持普通 Chat 和 Project 上下文模式。

Web 入口

用 bamboo web 启动浏览器对话界面并自动打开页面，默认访问 http://127.0.0.1:8899；用 bamboo docs 启动并打开使用说明页。

扩展和自动化

通过 skill、plugin、cron、eval 等子命令管理能力扩展、定时任务和回放测试。

快速开始

默认配置使用 kimi-k3 作为主模型。初始化后，只要在 models.yaml 里配置 Kimi API Key，或使用环境变量引用，就可以直接运行。 

pip install -e .
bamboo init

# 编辑 ~/.bamboo/configs/models.yaml，把 kimi-k3.api_key 改成你的 key，
# 或写成 "${MOONSHOT_API_KEY}" 后在 shell 里设置环境变量。
export MOONSHOT_API_KEY="your-kimi-api-key"

bamboo main --msg "帮我分析这个项目"

如果你要使用 DeepSeek、GPT、Claude、MiniMax、Mimo、Ollama 或 vLLM，需要先在 ~/.bamboo/configs/models.yaml 注册模型，再在 ~/.bamboo/configs/bamboo_main_agent.yaml 中把 model 改为对应的模型注册名。

配置模型

Bamboo 有两个关键配置文件。models.yaml 负责注册模型连接信息； bamboo_main_agent.yaml 负责选择主 Agent 实际使用哪个模型注册名。

1. 配置 models.yaml

文件位置：

~/.bamboo/configs/models.yaml

默认 Kimi 示例：

default_model: kimi-k3

models:
  kimi-k3:
    provider: kimi
    model: kimi-k3
    model_type: vision
    prompt_profile: kimi
    api_key: "${MOONSHOT_API_KEY}"
    base_url: https://api.moonshot.cn/v1
    timeout: 60
    context_window: 1000000
    max_tokens: 4096
    extra_body:
      reasoning_effort: max
    capabilities:
      tool_calling: true
      json_schema: false
      vision: true
      max_parallel_tools: 1
字段说明
default_model默认模型注册名，必须存在于 models 下。
provider模型供应商。支持 kimi、deepseek、minimax、mimo、gpt、claude、ollama、vllm。
model供应商侧的真实模型 ID。
model_type模型类型。文本模型填 text；能看图的模型填 vision。
prompt_profile提示词适配配置，通常和 provider 同名。
api_keyAPI Key。云模型通常必填；支持 ${ENV_NAME} 环境变量引用。ollama 和 vllm 可以为空。
base_url接口地址。云模型填官方或兼容接口地址，本地模型填本地服务地址。
timeout请求超时时间，单位秒。
temperature采样温度；不需要覆盖时可以保留默认值。
context_window上下文窗口大小。
max_tokens最大输出 token，必须小于 context_window。
extra_body透传给模型 API 的额外顶层参数，例如 Kimi K3 的 reasoning_effort。
capabilities声明模型能力，例如工具调用、JSON Schema、视觉输入和并行工具数。

2. 配置主 Agent

文件位置：

~/.bamboo/configs/bamboo_main_agent.yaml

默认配置：

model: kimi-k3
fallback_model: ""
compaction_model: ""
compaction_fallback_model: ""

auxiliary_models:
  compaction:
    model: ""
    fallbacks: []
  memory:
    model: ""
    fallbacks: []
  knowledge_curator:
    model: ""
    fallbacks: []
  skills_hub:
    model: ""
    fallbacks: []
  web_extract:
    model: ""
    fallbacks: []
  session_search:
    model: ""
    fallbacks: []
  vision:
    model: ""
    fallbacks: []
字段说明
model主 Agent 使用的模型注册名，必须在 models.yaml 中存在。
fallback_model主模型遇到 rate limit、server error、timeout 等可重试错误时的备用模型；留空表示不启用。
compaction_model上下文压缩使用的模型；留空时复用 model。
compaction_fallback_model上下文压缩的备用模型；留空表示不启用。
auxiliary_models为 memory、skills_hub、vision 等辅助任务指定模型；未配置时默认复用主模型。

3. 切换到其他云模型

例如使用 OpenAI 兼容的 GPT 配置：

# ~/.bamboo/configs/models.yaml
default_model: gpt-default

models:
  gpt-default:
    provider: gpt
    model: gpt-4.1-mini
    model_type: text
    prompt_profile: gpt
    api_key: "${OPENAI_API_KEY}"
    base_url: https://api.openai.com/v1
    timeout: 60
    temperature: 0.2
    context_window: 1047576
    max_tokens: 4096
    capabilities:
      tool_calling: true
      json_schema: true
      vision: false
      max_parallel_tools: 1
# ~/.bamboo/configs/bamboo_main_agent.yaml
model: gpt-default

4. 使用本地模型

Ollama 和 vLLM 可以通过发现命令生成模型注册片段：

bamboo models discover ollama
bamboo models discover ollama --write --set-default

bamboo models discover vllm --base-url http://localhost:8000/v1
bamboo models discover vllm --write --replace

--write 只写入 models.yaml。如果要让主 Agent 使用发现到的模型， 还需要把 bamboo_main_agent.yaml 里的 model 改成对应注册名。

bamboo main

启动 Bamboo 主会话。无消息时进入交互式 CLI；传入 --msg 时执行单轮任务。

bamboo main
bamboo main --msg "帮我总结这个仓库"
bamboo main --session-mode project --project /path/to/project
bamboo main --resume SESSION_ID
参数默认值说明
--msg, -mnull初始消息；不传时进入交互式 CLI 会话。
--project, -p当前目录项目路径，Project 模式会使用它作为上下文根目录。
--model主 Agent 配置临时覆盖本轮使用的模型注册名。
--provider模型配置临时覆盖 provider，例如 kimi、deepseek、gpt、claude。
--permissiondefault权限模式：default、auto、bypass、yolo。
--no-streamfalse禁用流式输出标记；具体支持取决于 provider。
--yes, -yfalse自动确认权限提示。
--debug-eventsfalse打印调试事件。
--session-modeauto会话模式：auto、project、chat。
--resumenull恢复指定 session id。
--record-dirnull显式指定持久化 session 目录。

bamboo run

运行一个单次命令行任务，适合脚本或快速提问。

bamboo run "检查测试失败原因"
bamboo run "继续刚才的分析" --resume SESSION_ID
参数默认值说明
TASK""任务描述位置参数。
--debug-eventsfalse打印调试事件。
--resumenull恢复指定 session id，并把 TASK 作为后续任务执行。
--record-dirnull显式指定持久化 session 目录。

bamboo web

启动 Bamboo Web 对话入口，并在系统浏览器中打开页面。命令会保持运行，按 Ctrl+C 停止服务。

bamboo web
bamboo web --host 0.0.0.0 --port 9000 --reload
bamboo web --no-browser
参数默认值说明
--host127.0.0.1Web 服务监听地址。
--port, -p8899Web 服务监听端口。
--reloadfalse启用 Uvicorn 自动重载，主要用于开发。
--no-browserfalse只启动服务，不自动打开浏览器。

bamboo docs

启动 Bamboo Web 服务，并在系统浏览器中打开使用说明页。命令会保持运行，按 Ctrl+C 停止服务。

bamboo docs
bamboo docs --host 127.0.0.1 --port 8899
bamboo docs --port 9000
bamboo docs --no-server
参数默认值说明
--host127.0.0.1Web 服务地址。
--port, -p8899Web 服务端口。
--no-serverfalse只打开文档 URL，不启动 Web 服务。适合已有 bamboo web 正在运行的场景。

bamboo replay

离线查看已持久化 session 的执行摘要，不调用模型或工具。不传 SESSION_ID 时会列出最近会话。

bamboo replay
bamboo replay list
bamboo replay latest
bamboo replay -1
bamboo replay -2
bamboo replay SESSION_ID
bamboo replay SESSION_ID --json
bamboo replay SESSION_ID --session-mode project --project /path/to/project
参数默认值说明
SESSION_ID可选要查看的持久化 session id；也可以传 latest/last 查看最近会话，传 -1/-2 按列表序号选择最近第 1/2 条。
list可选列出全部可发现 session，并显示负数序号和 session 主题。
--session-modeauto查找 session 时使用的模式。
--project, -pnullProject session 的项目路径。
--record-dirnull显式指定记录目录。
--jsonfalse输出原始 replay summary JSON。
--limit10不传 SESSION_ID 时列出的最近会话数量。

bamboo models

发现和写入本地 Ollama/vLLM 模型注册。

bamboo models discover ollama
bamboo models discover ollama --write --set-default
bamboo models discover vllm --base-url http://localhost:8000/v1 --timeout 10
参数默认值说明
provider必填本地 provider：ollama 或 vllm。
--base-url自动默认覆盖本地服务 base URL。
--timeout5.0发现请求超时时间。
--writefalse把发现结果写入 ~/.bamboo/configs/models.yaml。
--set-defaultfalse把第一个写入模型设置为 default_model。
--replacefalse替换同名模型注册。
--yes, -yfalse写入配置时跳过确认。

bamboo skill

命令参数说明
bamboo skill create NAME--description/-d，--overwrite创建 Skill 源目录和状态文件。
bamboo skill list--all列出 Skills；--all 包含 inactive 项。
bamboo skill install IDENTIFIER--trust，--force，--overwrite安装外部 Skill；--trust 支持 trusted、community、local。
bamboo skill scan PATH本地 Skill 目录扫描目录但不安装。
bamboo skill show NAMESkill 名称显示 Skill 定义和状态摘要。
bamboo skill validate NAMESkill 名称重新校验 Skill。
bamboo skill enable NAMESkill 名称启用 Skill。
bamboo skill disable NAMESkill 名称禁用 Skill。

bamboo cron

命令参数说明
bamboo cron start--interval 默认 30.0启动 heartbeat 调度器。
bamboo cron tick无执行一次调度检查并退出。
bamboo cron list无列出已注册任务。
bamboo cron add NAME--schedule/-s，--prompt/-p，--project，--session，--delivery，--session-id，--record-dir，--replace注册 Cron job。--session 和 --delivery 支持 isolated/main。
bamboo cron enable NAME任务名启用任务。
bamboo cron disable NAME任务名禁用任务。

bamboo plugin

命令参数说明
bamboo plugin validate PATH本地插件目录校验并扫描插件，但不安装。
bamboo plugin install PATH--force，--overwrite安装本地 Plugin。
bamboo plugin list无列出已安装插件。
bamboo plugin show NAME插件名显示已安装 Plugin 摘要。
bamboo plugin remove NAME--force卸载插件；默认保留用户修改过的已安装文件。

bamboo eval

命令参数说明
bamboo eval run CASE_DIR--json运行包含 input.yaml 和 expected.yaml 的 eval case。
bamboo eval export SESSION_ID CASE_DIR--session-mode，--project，--record-dir，--overwrite把已有 session trace 导出为 replay eval fixture。

其他命令

bamboo init初始化 Bamboo 用户目录和默认配置文件。
bamboo version输出当前 Bamboo 版本。
