Architecture And Runtime Flow

Bamboo 项目结构与执行流程

这份文档按当前代码状态整理 Bamboo 的完整组织方式和运行链路。它覆盖命令入口、Web 入口、 Runtime、Agent OTA 循环、模型路由、工具、权限、Memory、Skills、Plugins、MCP、Cron、Eval、 Replay、事件追踪和测试文件。目标是让阅读者从一个页面看清整个项目如何组织，以及一次请求如何流经系统。

更新日期：2026-07-08 入口：CLI / Web / Cron / Eval 核心：TaskRuntime + AgentRuntime 文档路径：docs/runtime-flow.html

总体视图

Bamboo 的代码按“入口适配、任务创建、运行时执行、模型路由、工具生态、持久化、扩展机制、自动化与评估”分层。 入口只负责把用户请求转为 RunParams 并渲染事件；核心执行由 TaskRuntime 和 AgentRuntime 负责；能力扩展通过 ToolRegistry、SkillRegistry、PluginInstaller、MCPManager 和 WorkflowRegistry 接入。

用户入口

bamboo/run.py 注册 CLI；adapters/cli 渲染终端；adapters/web 提供 Web UI、流式接口、权限审批和 docs 页面。

任务核心

factory 创建 Session/Context/Task；runtime 编排任务、Agent 循环、压缩、trace、subagent 和 task store。

能力系统

llms 管模型；tools 管内置和 MCP 工具；skills/plugins/workflows/subagents 管扩展能力。

TaskRuntime 主流程

TaskRuntime 是任务生命周期总控。它不直接拼 prompt、不直接执行工具，而是创建 task、启动 AgentRuntime、处理 trace、失败恢复、知识沉淀和收尾状态。

sequenceDiagram
    autonumber
    participant Entry as CLI/Web/Cron/Eval
    participant TR as TaskRuntime
    participant TF as TaskFactory
    participant SF as SessionFactory
    participant Store as TaskStore
    participant Trace as TraceRecorder
    participant Agent as AgentRuntime
    participant Knowledge as KnowledgeSubagent
    participant Bus as EventBus

    Entry->>TR: run(run_params) or run_existing_task(task)
    TR->>TF: create(run_params)
    TF->>SF: create(memory_dir_path, run_params)
    SF-->>TF: Session + Context + SessionMemoryStore
    TF-->>TR: Task
    TR->>Trace: start(session_id, task_id)
    TR->>Store: save_created(task)
    TR->>Bus: TaskCreateEvent
    TR->>Bus: TaskStatusChangeEvent created -> running
    TR->>Bus: StepStartEvent
    loop agent attempts
        TR->>Agent: run(task)
        Agent-->>TR: completed task
    end
    TR->>Bus: TaskStatusChangeEvent running -> completed
    TR->>Trace: append_turn(task)
    TR->>Knowledge: maybe_update(task) if enabled
    TR->>Bus: StepFinishEvent
    TR->>Trace: close()
    TR-->>Entry: Task
失败路径：Agent 抛错后先按 TaskRecoveryPolicy 尝试任务级恢复；耗尽后标记 failed，写 task trace，并发 StepFinishEvent 和 TaskStatusChangeEvent。取消路径会进入 cancelled。

Agent OTA 循环

AgentRuntime 执行 Observe -> Think -> Act 循环，直到 completed、failed 或 cancelled。每轮都会通过状态机发布状态事件。

stateDiagram-v2
    [*] --> created
    created --> observing
    observing --> compacting: context over budget
    compacting --> observing: summary saved
    observing --> thinking: prompt ready
    thinking --> acting: model response
    thinking --> compacting: context length error
    acting --> tool_calling: tool calls
    tool_calling --> observing: tool result appended
    tool_calling --> waiting: permission required
    waiting --> tool_calling: approved
    waiting --> observing: denied or resolved
    acting --> completed: final answer
    observing --> failed
    thinking --> failed
    acting --> failed
    tool_calling --> failed
    completed --> [*]
    failed --> [*]
    cancelled --> [*]
阶段 执行内容 核心代码
Observe 通过 AgentPromptBuilder 收集 system prompt、历史消息、工具说明、skills、memory、错误恢复历史。 runtime/agent_runtime.py、runtime/prompt.py
Compact 根据 token budget 主动压缩；遇到 LLMContextLengthError 时 reactive compact 后重试。 runtime/context_compactor.py
Think 调用主模型；遇到可 fallback 错误时激活 fallback；发 LLMRequestEvent/LLMResponseEvent。 runtime/agent_runtime.py、llms/router.py
Act: final text 写 assistant message，发 text events，设置 task.output，并进入 completed。 runtime/agent_runtime.py、factory/session.py
Act: tool calls 校验工具、权限策略、执行工具、写 tool message、发 ToolCall/ToolResult/ToolError/ToolAudit。 runtime/agent_runtime.py、tools/*、security/*

Replay 与会话查询

bamboo replay 直接读取持久化 session，不调用模型或工具。它通过 session metadata 的 updated_at 排序，所以旧目录名和新目录名都能读。

flowchart TD
    Cmd["bamboo replay ARG"] --> Arg{"ARG?"}
    Arg -- empty --> ListRecent["list recent sessions limit=10"]
    Arg -- list --> ListAll["list sessions limit=1000"]
    Arg -- latest/last --> Latest["find_latest_session_record"]
    Arg -- -1/-2 --> ByIndex["list_session_records sorted by updated_at -> index"]
    Arg -- session_id --> Find["find_session_record(session_id)"]
    Latest --> Summary["build_replay_summary(record_dir)"]
    ByIndex --> Summary
    Find --> Summary
    Summary --> Print["print counts + turns or JSON"]

Cron 与 Eval

Cron 和 Eval 都是普通任务入口之外的自动化入口。Cron 把计划任务转为 RunParams；Eval 可以 replay fixture，也可以 live 运行 TaskRuntime。

flowchart LR
    CronYaml["~/.bamboo/cron/jobs.yaml"] --> CronStore["CronStore"]
    CronStore --> Scheduler["CronScheduler.tick/run_forever"]
    Scheduler --> Delivery{"delivery"}
    Delivery -- isolated --> NewTask["new session task"]
    Delivery -- main --> Existing["restore latest or target session"]
    NewTask --> Runtime["TaskRuntime"]
    Existing --> Runtime
    Runtime --> CronRecord["CronRunRecord"]

    EvalCase["eval case"] --> EvalRunner["EvalRunner"]
    EvalRunner --> ReplayCase["mode=replay -> build_replay_summary"]
    EvalRunner --> LiveCase["mode=live -> TaskRuntime"]
模块 说明 关键命令
Cron CronJob 包含 schedule、prompt、project、session/delivery、target session、retry、metadata。scheduler 使用 croniter 判断 due run。 bamboo cron add/list/start/tick/enable/disable
Eval replay 读取 fixture 或 record_dir，生成 report，不调用模型。 bamboo eval run CASE_DIR
Eval export 把已有 session trace 导出成 eval fixture。 bamboo eval export SESSION_ID CASE_DIR

事件与 Trace

事件是 UI、日志、trace 和调试的公共接口。EventBus 不保存状态，只广播事件；状态保存在 TaskStore 和 SessionMemoryStore。

事件族代表事件用途
TaskTaskCreateEvent、TaskStatusChangeEvent、TaskStopEvent任务创建、运行、完成、失败、取消。
Session/StepSessionStatusChangeEvent、SessionCompactEvent、StepStartEvent、StepFinishEventAgent 状态、压缩、步骤开始和结束。
LLM/TextLLMRequestEvent、LLMResponseEvent、TextStartEvent、TextDeltaEvent、TextFinishEvent模型请求、响应、文本流。
Tool/PermissionToolCallEvent、ToolResultEvent、ToolErrorEvent、PermissionRequestEvent、PermissionResultEvent、ToolAuditEvent工具调用、结果、错误、审批和审计。
Cron/Subagent/Workflow/MemoryCronJobStartEvent、SubagentStartEvent、WorkflowRunStartEvent、KnowledgeUpdateEvent自动化、子任务、流程和知识更新。
事件 schema 的字段说明在 docs/agent-trace-events.md 和 docs/event-schema.md。TraceRecorder 会按 session_id/task_id 过滤事件并写入 events.jsonl。

阅读顺序建议

  1. 先看 bamboo/run.py，理解所有用户命令入口。
  2. 再看 factory/session.py 和 factory/task_factory.py，理解 Task/Session/Context 如何创建。
  3. 接着看 runtime/task_runtime.py 和 runtime/agent_runtime.py，理解任务生命周期和 OTA 循环。
  4. 然后看 runtime/runtime_context.py，理解模型、工具、memory、skills、subagents、MCP 如何装配。
  5. 最后按需要进入 llms、tools、memory、security、skills/plugins/workflows。

这份文档刻意覆盖全项目结构，不替代每个模块自己的单元测试和代码注释。若新增入口、配置、工具或持久化文件，应同步更新本页。
