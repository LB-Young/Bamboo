Bamboo 项目设计说明

本文档基于当前代码状态整理，用于说明 Bamboo 的已有架构意图、模块职责、运行链路以及目前尚未闭合的设计点。

项目定位

Bamboo 是一个 Python 实现的个人 AI Agent 助手项目。当前包元信息将其描述为 AI-powered personal agent assistant，命令行入口暴露为 bamboo。

从目录和依赖看，项目目标不是单纯聊天机器人，而是一个支持 CLI、配置化模型/工具/技能/子代理/工作流、用户空间、事件流和记忆存储的 Agent 运行框架。

当前实现仍处于骨架阶段：部分核心类已经有结构定义，但 CLI 会话执行链路、MemoryWatcher、gateway、LLM 调用、工具执行和工作流调度尚未完整接入。

技术栈

类别 当前选择 用途

bamboo/adapters/cli CLI adapter，负责把命令行参数转换为运行参数并启动会话。 有会话启动草稿，但依赖未实现对象。

启动与运行链路

当前可见的启动入口主要有两条：

  1. bamboo init 调用 ensure_userspace()，创建 ~/.bamboo 下的配置、工具、技能、子代理、工作流、存储、记忆、日志和工作区目录。
  2. bamboo run [task] 调用 bamboo.core.run_agent(task)，目前只打印占位信息。

预期中的会话启动链路

bamboo.run.main() 中还定义了一套更完整的参数入口，会生成 RunParams，再通过 anyio.run(_start_session, run_params) 进入 CLI adapter。

CLI 参数
  -> RunParams
  -> adapters.cli._start_session()
  -> TaskFactory.create()
  -> SessionFactory.create()
  -> Agent processor / stream / repl
  -> EventBus 输出事件
这条链路当前没有被 Typer app 注册为默认 callback；并且 _start_session() 中引用了 get_config、SessionFactory gateway、MemoryWatcher、session_mode、project、model 等未定义或未存在对象，因此还不能作为真实运行路径使用。

核心对象模型

RunParams

RunParams 是 CLI 到任务工厂之间的参数载体，包含平台、消息、项目路径、模型、供应商、权限模式、流式开关、自动确认、会话模式、任务 ID 和会话 ID。

当前类是普通类属性定义，尚未使用 dataclass 或 Pydantic，因此没有初始化校验、默认值隔离和类型强制。

TaskFactory 与 Task

TaskFactory.create() 根据 session_mode 选择项目级或日期级记忆目录，然后创建 Session，并组装 Task。

设计意图是把一次用户请求抽象为任务对象，让任务持有运行配置、会话对象、输入和输出。

SessionFactory 与 Session

Session 当前保存 session_id、model、provider 和 context。SessionFactory 负责创建 Context 并注入 Session。

该层未来应承担会话状态、上下文更新、消息历史和模型运行状态管理。

Context 与 Message

Context 目前只有名称和 build_context() 占位逻辑。Message 支持记录 agent 名称、消息 ID、角色、内容，并能标记为已压缩消息。

这两个对象共同指向后续的上下文压缩、消息追踪和多 Agent 协作能力。

事件体系

项目已经定义了一套较完整的事件模型，所有事件基于 BaseEvent，包含 type、session_id、timestamp、event_id、step_id、task_id 和平台信息。

事件类别 代表事件 用途
文本输出 TextStartEvent、TextDeltaEvent、TextFinishEvent 支持流式文本渲染。
推理过程 ReasoningStartEvent、ReasoningDeltaEvent、ReasoningFinishEvent 表达模型推理流或中间思考内容。
工具调用 ToolCallEvent、ToolResultEvent、ToolErrorEvent 追踪工具输入、输出和错误。
执行步骤 StepStartEvent、StepFinishEvent 表达 Agent 分步执行和文件变更摘要。
系统状态 SessionCompactEvent、SessionStatusChangeEvent、AuditEvent 处理上下文压缩、状态变更和审计记录。
计划与工作流 PlanStartEvent、WorkflowRunStartEvent 等 支持计划确认、步骤执行和工作流断点。
任务状态 TaskCreateEvent、TaskStatusChangeEvent 表达任务生命周期。

EventBus 使用订阅者列表和异步锁管理事件发布，支持按事件类型、过滤函数订阅，也支持按 session_id 流式消费事件。

用户空间与配置设计

ensure_userspace() 会在用户主目录下创建 ~/.bamboo，并规划如下主要目录：

  • configs：用户可编辑配置。
  • buildin_tools、buildin_skills、buildin_subagents、buildin_workflows：内建扩展内容。
  • tools、skills、subagents、workflows：用户安装或 Agent 创建的扩展。
  • storage/projects、storage/dates：项目级和日期级结构化存储。
  • memory：全局记忆目录。
  • tasks、logs、workspace：任务队列、日志和默认工作区。

BambooConfig 会从 ~/.bamboo/configs/*.yaml 加载 YAML 配置，并按文件名 stem 存入字典，例如 models.yaml 对应 config["models"]。

日志与安全

日志系统基于 Loguru，支持控制台输出、文件输出、异步队列、日志轮转和保留策略。

RedactingFilter 会对常见敏感信息做正则脱敏，包括 OpenAI/Anthropic key、GitHub token、Slack token、AWS key、Bearer token、API key、password/secret 等。

这是当前项目中较明确的安全设计：把凭据泄漏风险放在日志层统一处理。

当前主要未完成点

  • pyproject.toml 的 setuptools package 列表只包含部分包，未包含 factory、helpers、userspace、memory 等已被导入的包，打包后可能缺文件。
  • RunParams 中字段名为 platfrom，但 TaskFactory 读取 platform；TaskFactory 还读取 user_query，但 RunParams 中是 message。
  • TaskFactory.create() 是实例方法，但 _start_session() 使用了 TaskFactory.create(...) 类方法调用形式。
  • SessionFactory.create() 的函数签名和调用参数不一致，并且最终 return self.session() 会把 Session 实例当函数调用。
  • Context() 当前构造函数需要 name，但 SessionFactory 未传入。
  • memory/get_memory_path.py 使用了 platform 和 datetime，但没有 import。
  • adapters/cli/main.py 引用了不存在或未导入的 get_config、gateway.SessionFactory、MemoryWatcher 和流式执行函数。
  • bamboo/core.run_agent() 仍是占位实现，尚未接入真正的 Agent loop。
  • 包内 YAML 配置文件目前为空，用户空间初始化后也只能复制空模板。
  • 项目名在部分文案里仍出现 AutonCode 或 Auton Core，与 Bamboo 命名不一致。

建议的演进顺序

  1. 先统一数据模型：将 RunParams、Task、Session、Message 改为 dataclass 或 Pydantic model，并修正字段命名。
  2. 修通最小 CLI 执行链路：bamboo run "task" 能创建 task/session/context，并通过 EventBus 输出文本事件。
  3. 修正打包配置：使用自动发现包，或补齐 setuptools packages。
  4. 补充默认 YAML 模板：至少包括 models、tools、skills、subagents、workflows 的最小结构。
  5. 实现 LLM provider 抽象：把 OpenAI、Anthropic 等客户端接入统一接口。
  6. 实现 memory 和 storage 的边界：明确项目级、日期级、全局记忆分别保存什么。
  7. 在 CLI 稳定后再扩展 Web adapter、工作流调度、工具权限和审计能力。
